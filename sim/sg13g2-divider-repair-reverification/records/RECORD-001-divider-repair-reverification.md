# RECORD-001: SG13G2 (non-port) `divider_chain` repair (issue #120) — hold, division, and OP convergence re-verified on the SG13G2 PDK

- **Slug**: `sg13g2-divider-repair-reverification`
- **Issue**: #120 (Part of #16) — ports #112's repair (merged there via PR
  #121) from `design/sg13cmos5l/dff_tg_hv.sch` to the SG13G2 (non-port)
  `design/dff_tg_hv.sch`. The port campaign's RECORD-003 documented this
  exact defect as "verified against the worktree ... filed as #120, out of
  this record's scope"; this record is that scope.
- **DUT**: `divider_chain` as **repaired in `design/` by this record's own
  PR** — frozen at `../netlist-snapshots/divider_chain_repaired.spice`
  (regenerated by `design/netlist.sh` at base commit `8cced83`,
  `origin/main` tip this PR branches from). The repair adds, inside every
  `dff_tg_hv`: (a) the missing second feedback inverter in each latch's hold
  path (`XIMF`, `XISF` — full-strength `inv_hv`), and (b) the missing second
  local clock phase (`XICKBB`: `CKBB` = `CLK` delayed two inverter delays)
  with all four transmission gates staggered on it exactly as the proven
  fleet topology (gf180-pll `dff_tg_3v3`).
- **Tooling**: `ngspice-46`, `PDK_ROOT=/home/ubuntu/share/pdk`,
  `PDK=ihp-sg13g2`.
- **Reproduce**: `PDK_ROOT=<pdk-root> PDK=ihp-sg13g2 ./testbench/run.sh`
  (stages: `opconv hold func`; default all three). The harness is the
  SG13G2 twin of `sim/sg13cmos5l-divider-nrange-retiming/testbench/run.sh`
  (#36/#112), same decks, same 9-point PVT matrix (see `../corners/matrix.md`).

## The repair

Identical in substance to the port's #112 repair — see
`sim/sg13cmos5l-divider-nrange-retiming/records/RECORD-003-divider-repair-reverification.md`
§ "The repair" for the full narrative (one-inversion self-biased hold loops
bounded non-functional by that campaign's RECORD-001 Finding 2; two-inversion
feedback + staggered `XICKBB` phase verified by its RECORD-003). The circuit
edits here are a **verbatim port**: every instance line (`C {...}`) of
`design/dff_tg_hv.sch` after this PR is byte-identical to the merged
`design/sg13cmos5l/dff_tg_hv.sch` — verified by `diff <(grep '^C {'
design/dff_tg_hv.sch) <(grep '^C {' design/sg13cmos5l/dff_tg_hv.sch)`
returning empty. Only the header comment differs (repo-specific issue/PR
references).

## Why the port campaign's whole-chain numbers transfer exactly

Three independent byte-identity checks, re-run in this record's own session
(commands verbatim, paths relative to the repo root):

1. **DUT netlist**: `diff <(grep -v '^\*'
   design/netlist/divider_chain.spice) <(grep -v '^\*'
   sim/sg13cmos5l-divider-nrange-retiming/netlist-snapshots/divider_chain_repaired.spice)`
   — every non-comment line (all `.subckt`, device, and instance lines) is
   **byte-identical** to the frozen snapshot the port's RECORD-003 PVT-swept.
   Only provenance comments and `sch_path`/`sym_path` annotations differ
   (the port prefixes its paths with `sg13cmos5l/`; DR-004's pure-hierarchy
   port changed no electrical content).
2. **Model cards**: every model file this campaign's decks actually load is
   **byte-identical** between `ihp-sg13g2/` and `ihp-sg13cmos5l/` (`cmp` per
   file): `cornerMOShv.lib` itself, and — per its plain corner sections'
   own `.include` lines, the only sections any deck here selects
   (`mos_tt`/`ss`/`ff`/`sf`/`fs`, never the `_mismatch`/`_stat` variants) —
   `sg13g2_moshv_mod.lib` and `sg13g2_svaricaphv_mod.lib`. (The CMOS5L tree
   literally ships the `sg13g2_*` model files — it is a CMOS-only
   repackaging of SG13G2. One file outside this closure,
   `sg13g2_svaricaphv_mismatch.lib`, does differ between the trees; it is
   reachable only via the `_mismatch` corner sections no deck in this
   campaign or the port's selects.)
3. **OSDI objects**: `psp103.osdi`, `psp103_nqs.osdi`, `mosvar.osdi` are
   **byte-identical** between the two trees (the port's own
   `sim/README.md` notes they are "host-local build products of the sibling
   `ihp-sg13g2` tree").

Consequently the port RECORD-003 numbers for the stages this session did not
re-run fresh (its 9-word code sweep, `111111` PVT edge brackets at
`mos_ss/125C` and `mos_ff/-40C`, the `tol_convergence` arms, and the
`setup`/`retime` stages) are the **same simulation** — identical deck text
after PDK-path substitution, identical models, same ngspice — and are cited
as such. This is the same cross-PDK identity pattern
`sg13g2-vco-kvco-table/records/RECORD-001` already established and
documented ("byte-for-byte identical ... because both designs' active
devices and corner-model files are literally shared between the two PDK
trees").

## Compute scoping of the fresh `func` stage (stated, not silent)

This record's host ran contended (8 cores, sustained load average 11–22 from
co-tenant builds and workers), and a single whole-chain transient
(~218–430 CKIN cycles, 316 devices) took 9–20+ wall minutes — the same
compute-bound reality the port campaign's own header and
`corners/matrix.md` document for the same decks. The fresh `func` rows are
therefore a **bounded, decision-grade subset** of the port's 20-row matrix:

- the `N=64` baseline at the 3 speed-bracket process corners
  (`mos_tt`/`mos_ss`/`mos_ff` @ 27C/3.3V), and
- the structural-range bracket at nominal: the LSB word (`000001`, `N=65`),
  the MSB word (`100000`, `N=96`), and the range ceiling (`111111`, `N=127`).

Not freshly re-run (covered by the identity transfer above): the remaining
6 PVT points of the `N=64` baseline (temp/supply extremes and the
`mos_sf`/`mos_fs` split corners), the remaining 6 code-sweep words, the two
`111111` temp-extreme edge brackets, and the tolerance arms. The committed
`testbench/run.sh` reproduces the full set sequentially on an idle host
(`RESUME=1` re-enters after interruption); this session's fresh rows were
produced by a session-local parallel scheduler running the identical
template decks, and `corners/func.csv` carries only rows emitted by those
actual ngspice runs.

## Spec disposition

`spec/porting-plan.md` row 3's functional-`N` half: the SG13G2 (non-port)
divider's committed design now divides at exactly its commanded `N` at every
freshly simulated point (speed-bracket process corners at the `N=64` floor,
plus the `N` = 65/96/127 structural bracket at nominal) — matching the port
campaign's already-closed functional claim for the identical netlist. The
retiming-margin numeric sub-bound at the top-of-band frequency **remains
open** exactly as the port's RECORD-003 left it (one-edge capture fails;
one-period-late `k+2` capture observed; sizing re-derivation owed to the
device-characterization campaign per DR-001). Not relaxed; stated as
measured — by the port record for the identical DUT, and now by this record
for the same netlist on the SG13G2 tree.

Row 11 (`divider_chain` power domain): the fresh 100 MHz rows bound average
supply current at −218.6 … −237.7 µA, inside the port record's 9-corner
range (−199.3 … −256.8 µA) for the same operating point.
