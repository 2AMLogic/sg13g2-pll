# RECORD-005: `XRPU` bulk re-declared on `VSS` (LVS repair) — nominal-corner re-verification, full grid not run

- **Slug**: `sg13cmos5l-lock-detector-window`
- **Issue**: #136 (Part of #16). Supersedes nothing. `RECORD-004` (#76) stays
  the full-PVT evidence for row 16 and row 11; this record measures whether
  #136's schematic change moved anything, at the one corner this host is
  permitted to run, and states plainly what it did **not** run.
- **What changed in the DUT, and why.** The SG13CMOS5L layout's
  `lock_detector` LVS compare reported `PU` (`rhigh`) unmatched and a
  reference-only net `SUB!`: `lock_detector.sch` declared `RPU`'s bulk on a
  private floating `sub!` global, while a drawn `rhigh`'s bulk is the
  p-substrate, which the layout ties to `VSS` through every NMOS group's
  substrate tap — the same family #113 repaired in `vco_bias.sch`. #136
  re-declares that one bulk terminal on `VSS`. (The other half of the
  baseline mismatch — `PD`'s two open diffusion terminals — was a layout
  footprint defect with no schematic content; see
  `layout/sg13cmos5l-pll/README.md`.)
- **DUT**: `../netlist-snapshots/lock_detector_bodyfix.spice`, frozen from
  `design/sg13cmos5l/netlist/lock_detector.spice` (regenerated by
  `design/sg13cmos5l/netlist.sh` from the edited schematic) at this record's
  own branch HEAD. It differs from `RECORD-004`'s
  `lock_detector_crowbarfix.spice` in **exactly one line**:

  | Device | RECORD-004 (was) | RECORD-005 (now) |
  |---|---|---|
  | `XRPU` (`rhigh`, `w=0.5u l=700u`) | `XRPU VDD VWIN sub! rhigh …` | **`XRPU VDD VWIN VSS rhigh …`** |

  No size, no signal connection and no other bulk changes.
- **Why little can move, stated before measuring.** Every testbench in this
  slug declares `.global sub!` with `Vsub sub! 0 0`, and every
  `lock_detector` copy (`tb_lock_recovery`, `tb_lock_ladder_point` via
  `gen_ladder.py`, `tb_hyst_diag`) wires its `VSS` pin to node `0`. Old and
  new bulk nodes are therefore both an ideal 0 V; the only difference the
  simulator sees is one fewer voltage-source branch in the MNA matrix the
  rhigh bulk hangs off. The decks that do not instantiate `lock_detector`
  at all — `tb_window` (bare `delaywin_hv`), `tb_schmitt_hyst` (bare
  `schmitt_hv`), `tb_extract_r`/`tb_extract_c` (bare devices) — contain no
  `XRPU` instance from the DUT and cannot change. That argument is not
  offered as evidence; the measurement below is.
- **Claim under test**: `spec/porting-plan.md` row 16 (assert window ≥ 2.5 ns,
  hysteresis ≥ 25 % of window, no chatter) and row 11 (`lock_detector`
  power domain), at **unchanged** thresholds and the **unchanged** corner
  matrix definition. No spec row was relaxed.
- **Tooling**: `ngspice-46` (`/home/ubuntu/.local/bin/ngspice`), installed
  `~/share/pdk/ihp-sg13cmos5l`, x86-64 Linux host (so `cap_cmomi.osdi` loads
  and the primary DUT variant is `real`, as in `RECORD-004`),
  `set num_threads=1`, the same `itl4=5000 gmin=1e-11` options.
- **Reproduce**:
  `NOMINAL_ONLY=1 PDK_ROOT=<pdk-root> PDK=ihp-sg13cmos5l ./testbench/run.sh`
  (113 s wall, sequential, `LADDER_JOBS` unset = 1) writes
  `../corners/rc_extract_bodyfix_nominal.csv` (3 rows),
  `window_bodyfix_nominal.csv` (1), `ladder_bodyfix_nominal.csv` (1),
  `ladder_raw_bodyfix_nominal.csv` (21), `schmitt_bodyfix_nominal.csv` (1),

  `solver_retries_bodyfix_nominal.txt` (empty — no deck needed the `trtol=1`
  retry). `NOMINAL_ONLY` is new in this record (see `run.sh`'s header): it

## Why only one corner was run (and what would run the rest)

This campaign's full grid is ~120 window decks, 21 ladder corners × 22
decks and 45 Schmitt decks. This record was produced on one of the fleet's
shared 8-vCPU dispatch workers, whose host rules require any multi-corner
SPICE grid to be submitted to the Spot batch fleet through `klt sim`
(`KLT_SIM_BACKEND=batch`) and forbid looping `ngspice` over a grid locally;
a single corner may run locally. Expressing this grid as a `klt sim`
request is not reachable for this PDK today: `klt sim`'s `batch`/`remote`
backends refuse `ihp-sg13cmos5l` before submission —

```
unsupported PDK 'ihp-sg13cmos5l' for the batch backend (supported: sky130A, gf180mcu, sg13g2)
```

(`klt 0.6.0+gc2d79eadcb06`, `remote_launcher.SUPPORTED_PDKS`). Filed
upstream per the friction protocol as
**[klayout-tools#2727](https://github.com/2AMLogic/klayout-tools/issues/2727)**
(generic: no published image for the `sg13cmos5l` family; sibling of
klayout-tools#2570 for `ihp-sg13g2`). `run.sh` now refuses the full grid on
a host that exports `KLT_SIM_BACKEND=batch` unless `NOMINAL_ONLY=1` (or
`ALLOW_LOCAL_GRID=1` asserts a dedicated simulation box), so the next agent
on such a host gets that diagnosis instead of a 21-corner local run.

**Owed**: `./testbench/run.sh` (full grid, writes `*_bodyfix.csv`) on a
dedicated simulation host, or via `klt sim --backend batch` once
klayout-tools#2727 lands, appended as a later record. Until then the
full-PVT row-16/row-11 verdicts remain `RECORD-004`'s, carried over on the
argument and the nominal-corner identity below — not re-measured.
