# Issue #136 — root cause of the SG13CMOS5L `lock_detector` LVS mismatch

Raw evidence for the diagnosis summarised in `../../README.md` ("Re-run for
issue #136"). Nothing here is a layout record: the two records it reads are
`../../reports/20260923-020931-a95a887-dirty/` (the baseline, **before**) and
`../../reports/20261003-183059-dc5644a/` (this issue's full re-run,
**after**), both untouched. Every `*.lvs.json` below is the unedited
`klt lvs --format json` response to the request file beside it (pinned klt
`0.6.0+gdaf06a51afaf`, klayout 0.30.12 — the same engine the baseline record
used).

## The hypothesis was half right

The issue framed the residual as one substrate split (`SUB!` versus the
layout's single substrate node, "stranding `PU`/`PD`"). Crossing the two
GDS files with the two references separates it into **two independent
defects**, each owning a disjoint subset of the five errors:

| Request | Layout | Reference | Devices | Nets | Error-severity mismatches |
|---|---|---|---|---|---|
| `baseline-repro` | before | before | 39/41 | 19 matched (25 layout / 24 ref) | `PD` (nfet) unmatched, `PU` (rhigh) unmatched, layout nets `$13`, `$28` unmatched, reference net `SUB!` unmatched — **identical** to the committed baseline `lvs.lock_detector.json` |
| `old-gds-new-ref` | before | after (`RPU` bulk on `VSS`) | 40/41 | 20 (25 / 23) | `PD`, `$13`, `$28` |
| `new-gds-old-ref` | after (contacted `PD`) | before (`RPU` bulk on `sub!`) | 40/41 | 20 (23 / 24) | `PU`, `SUB!` |
| record `lvs.lock_detector.json` | after | after | **41/41** | **23/23** | none (`topology.flattened` warning only) |

1. **`PU` + `SUB!` — the substrate split (schematic).** `lock_detector.sch`
   declared `RPU`'s bulk on the private floating `sub!` global. The drawn
   `rhigh`'s bulk extracts onto the substrate, which every NMOS group's
   substrate tap ties to `VSS` (`R$41 VDD VWIN VSS … rhigh` in both
   extractions), so the reference carried a second substrate node the
   layout cannot have. Same family as #113's `vco_bias` repair. Fixed in
   the source schematic; `lock_detector.spice` regenerated by
   `design/sg13cmos5l/netlist.sh` (one line). `pll_lock_detector.gds` alone
   with the corrected reference clears exactly these two errors.

2. **`PD` + `$13` + `$28` — an open device, not a substrate effect
   (layout footprint).** The baseline extraction reads
   `X$1 $28 WIDE $13 VSS sg13_hv_nmos L=16U W=0.25U`: both diffusion
   terminals of `XMPD` sit on nets with nothing else on them.
   `probe-terminal-geometry.txt` shows why, in the drawn geometry:
   - the `w=0.25u` group cell carries **zero** source/drain (and tap)
     contacts — `cmos5l_devices.cont_row` returns 0 for a span narrower than
     one `Cnt_a` + 2 × `Cnt_c` (0.30 µm), silently;
   - the source/drain riser columns sit 0.45 / 1.05 µm from the active edge
     (`pll_cmos5l_layout.SOURCE/DRAIN_RISER_DX_UM`, sized for the old 2 µm
     narrowest device), i.e. **off** a 0.25 µm pad: **2 `Via1`s land on no
     `Metal1` at all**.

   Both slipped through DRC: the curated deck has no `Cont` rule (`6/0` is
   under `coverage.layers_in_stream_without_rules`), and its
   `metal1.enclosing.via1.1` only flags a via that *partially* overlaps
   Metal1 — a via on nothing passes, filed as
   [klayout-tools#2726](https://github.com/2AMLogic/klayout-tools/issues/2726).
   The group-level re-extract check counts devices and `(class, W, L)`, so it
   passed too. The defect dates from #66's `XMPD` resize to `w=0.25u`; it is
   a property of this repo's own footprint code, not of the deck or the
   schematic. Fixed in `layout/bin/cmos5l_devices.py` (dog-bone contact
   heads on a device narrower than one contact row, a Metal1 tab out to each
   riser column, a contactable tap floor, and a hard error on any
   uncontacted terminal) — a no-op on every device ≥ 1.2 µm wide, so every
   other GDS in the record is byte-identical to the baseline's.

## Reproduce

```bash
cd layout/sg13cmos5l-pll/diagnosis/issue-136
for n in baseline-repro old-gds-new-ref new-gds-old-ref; do
  ../../../.venv/bin/klt lvs $n.lvs.request.json --format json > $n.lvs.json

../../../.venv/bin/python probe-terminal-geometry.py \
  ../../reports/20260923-020931-a95a887-dirty/pll_lock_detector.gds \
  ../../reports/20261003-183059-dc5644a/pll_lock_detector.gds
```
